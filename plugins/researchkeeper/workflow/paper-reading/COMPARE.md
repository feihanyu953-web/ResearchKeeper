# COMPARE 多篇横向对比协议

本文件承载"N 篇论文围绕同一主题的横向对比与综合"规则。触发场景：用户提出"对比这几篇""这个主题各家的结论一致吗""帮我梳理某方向的研究现状/争议/空白"。

与综述拆解的区别：综述拆解处理**一篇综述论文**（`workflow/paper-reading/READING.md`）；本协议处理**一个主题下的多篇论文**，且**以 kb 为数据源，不重读 PDF**。

## 前置条件

- 明确声明覆盖率：kb 命中 X 篇相关论文；若用户指定的论文未入库，明确标注"kb 未收录"，不假装覆盖。
- 常驻查询服务可选（`rsk serve`，见 `workflow/vector/VECTOR.md`）；`rsk search` 未连接服务时自动回退本地加载。

## 执行流程

### Step 1：界定主题与子问题

把用户的主题拆成 2-5 个可检索的子问题。例如"Na⁺ vs K⁺ 界面水效应"拆为：阳离子对界面水结构的影响 / 阳离子对反应动力学的影响 / 实验与计算证据是否一致。

### Step 2：向量检索（每个子问题各一轮）

```powershell
rsk search "<子问题>" --claims --top 5 --expand
```

claims 未命中的子问题用 papers 兜底：`rsk search "<子问题>" --top 5`。

### Step 3：精读 schema 行 + 评价类记录

- 对每条相关 record_id，Read 对应 kb 文件提取完整 13 字段行（事实层）。
- 同步提取该 paper_id 的**评价类记录**（创新代价 / 审稿质疑 / 异常归因等，
  由 `workflow/knowledge/INGEST.md` Step 3.5 产出；旧 6 模块工作区位于
  literature 模块），attribution 标签必须保留到输出中。
- 评价类记录是判断题的证据源：`attribution:作者` 可当论文立场引用；`AI审稿视角` / `AI推测` 必须带标签转述。

### Step 4：输出结构

```text
【覆盖率声明】本主题 kb 命中 X 篇：paper_id 列表；未收录：Y 篇（如有）

1. 逐篇提要（每篇 3-5 行）
   - paper_id：体系 / 方法 / 核心结论（带 record_id）

2. 一致性与差异对比（分栏）
   - 一致点：……（record_id）
   - 分歧点：……（record_id）

3. 观点谱系 / 争议轴（2-4 条）
   - 争议轴 1：[命名，如"界面水是参与反应还是调控反应"]
     - 立场 A：……（代表 paper_id）
     - 立场 B：……（代表 paper_id）

4. 差异来源解释
   - 方法 / 模型设定 / 工况 / 评价口径差异（每条锚定 record_id）

5. 研究空白主题归纳（3-6 类）
   - 类别：一句话核心问题 + 支撑 paper_id + 出现频次

6. 个人启发（5-8 条，按 Impact × Effort 降序）
   - 洞见（一句话）/ 迁移方式 / 行动步骤（1-3 步含关键参数）/ 风险前提
   - Impact（1-5）/ Effort（1-5）/ 证据链（record_id 列表）

7. 组合策略（≥5 条，每条 ≥2 篇互证）
   - 策略名 / 为什么更强（互补逻辑）/ MVP 三步实验（含关键参数或阈值）
   - 判停阈值（失败标准）/ 主要风险或证据冲突 / 证据链（record_id）
```

用户只要求"对比结论"时，输出 1-4 即可；5-7 在用户要求"启发/建议/下一步做什么"时输出。

## 硬规则

- 所有结论带 record_id 或外部来源 URL；kb 未覆盖的内容明确标注"当前未在该层查到证据"。
- 结论冲突时**并列呈现**，标注各自 record_id 与可能原因（工况 / 方法 / 口径差异），不擅自仲裁。
- `attribution:AI推测` 的内容必须带 `[AI推测]` 标签转述，不得表述为论文事实。
- 启发与组合策略是 AI 生成内容，证据链列 record_id 供核查；策略中的关键参数必须来自 kb 记录或显式标注"建议值"。
- 用户要求纳入未入库论文时走外部检索路径（学术搜索 → WebFetch → WebSearch → 本地 Zotero），并标注证据状态（仅摘要 / landing page / 全文）。
